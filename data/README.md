# Synthetic datasets

Only small, reviewable evidence fixtures belong in source control.

- `smoke/v1/` is the committed, deterministic source-contract v1 bundle plus
  its public scenario manifest, used by tests and early import development.
- `generated/`, `performance/`, `raw/`, and `uploads/` are ignored because they
  may be large, local, transient, or user supplied.

The documented demo bundle belongs under `generated/demo-v1/`; the 100,000
invoice functional-scale bundle belongs under `performance/performance-v1/`.
Their versioned profiles are committed under `generator/profiles`, but their
generated bytes are reproducible outputs and must remain untracked.

All repository-authored datasets are synthetic. Do not place personal,
customer, credential, production, or otherwise sensitive data in this tree.
Regenerate the smoke files from the versioned profile by following the
[generator guide](../generator/README.md).

Expected outcomes are deliberately absent from this public data tree. The smoke
oracle is test-only, checksum-bound evidence under `backend/src/test`; production
code must derive results from source data and controls rather than read answers.
